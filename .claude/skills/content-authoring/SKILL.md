# Контент курса — добавление и правка

## Зачем

Темы / уроки / слова / теория / кросс-предложения — единый источник правды в
[`convex/content.ts`](../../../convex/content.ts), заливается в таблицы Convex
**идемпотентным** сидом ([`convex/seed.ts`](../../../convex/seed.ts), upsert по
натуральным ключам). Подсистема целиком — baseline-спека
[`content-and-seed.md`](../../../specs/feature/content-and-seed.md) (источник правды;
держи в синхроне при правках).

## ⚠️ Несокращаемые правила стабильности (нарушение тихо ломает прогресс)

Прогресс пользователя завязан на натуральные ключи `(lessonKey, pt)`, НЕ на Convex
`_id` (ре-сид может пересоздать `_id`). Поэтому:

- **НЕ менять существующие `lesson.id` (= `lessonKey`) и `word.pt`.** Переименование
  осиротит весь накопленный прогресс по этому уроку/слову. Опечатку в `pt`
  существующего слова чинить можно ТОЛЬКО через миграцию прогресса, не правкой
  на месте.
- **`CROSS_SENTENCES` — только дописывать в КОНЕЦ.** `sentenceKey = cs_NNNN`
  выводится из индекса массива; вставка/удаление в середине сдвинет ключи у всех
  последующих предложений.
- **Свободно можно:** добавлять новые темы/уроки/слова/предложения; править `ru`,
  `note`, `theory`, `label`, `icon`, `answer`, `words`-плитки — всё, что НЕ ключ.

## Форма данных

Типы в [`content.ts`](../../../convex/content.ts): `Word { pt, ru, note? }`,
`Theory { intro, tip, sections[] }`, `Lesson { id, label, theory, words[] }`,
`Topic { label, icon, lessons[] }`, `CrossSentence { words, answer, ru, required }`.
Экспортируются `TOPICS` (`Record<string, Topic>`) и `CROSS_SENTENCES`. До ~10 слов
на урок. `order` для отображения **захватывается из порядка итерации** (порядок
ключей `TOPICS`, порядок массивов `lessons`/`words`) — добавляй в осмысленное место
последовательности, а не «куда попало».

## Язык: европейский португальский, с диакритикой

- Только **европейский** вариант (pt-PT), не бразильский. Озвучка форсит pt-PT.
- Диакритика **обязательна и точна**: `á ã â à é ê í ó õ ô ú ç` (`não`, `obrigada`,
  `irmã`, `café`). Это не косметика — `pt` участвует в ключе и в сверке ответа.
- `note: undefined` на ре-сид трактуется как «поля нет» (а `patch` чистит устаревшую
  заметку) — оставлять `note` отсутствующим, если заметки нет.

## Кросс-предложения (тонкий готч `required`)

`required` — массив **точных существующих `word.pt`**, которые должны быть выучены,
чтобы предложение всплыло. Если значение в `required` не совпадает буква-в-букву с
реальным `word.pt` (включая слэш-формы вроде `"dois / duas"`, `"bom / boa"`, и
регистр/диакритику) — предложение **никогда не появится** (гейт сверяет по множеству
выученных `pt`). `words` — токены-плитки (пунктуация прилипает к токену: `"dia!"`,
`"bem,"`), `answer` — полная строка-эталон, `ru` — перевод. Предложение показывается
при освоении темы на **≥80%** и всех выученных `required`
(`SENTENCE_TOPIC_THRESHOLD`, см. [`session-queue-and-rotation.md`](../../../specs/feature/session-queue-and-rotation.md)).
`SentenceBuilder` на сервер прогресс НЕ пишет — влияет только на счёт сессии.

## Сид и деплой (нет «горячей» правки)

Правка `content.ts` катится только так: PR → мёрж в `main` → CI прогоняет
`seed:seedContent` на проде. Локально проверить заливку: `npx convex run
seed:seedContent` (идемпотентно). Деплой и сид — см.
[CLAUDE.md → Деплой](../../../CLAUDE.md).

## Тесты (обязательно, в том же PR)

- [`convex/seed.test.ts`](../../../convex/seed.test.ts) — идемпотентность (повторный
  `seedContent` даёт те же счётчики, без дублей строк) и корректность upsert.
- [`convex/courseQueries.test.ts`](../../../convex/courseQueries.test.ts) — форма и
  порядок дерева `getCourse`.

Для чисто-контентных правок (добавил слова/тему, не трогая код сида) эти структурные
тесты остаются зелёными как есть — прогони `npm run test:backend`, убедись. Если
меняешь **форму** контента или код сида (новое поле, новый вид сущности) — расширь
тесты под это. Тест-политика — [`../test-policy/SKILL.md`](../test-policy/SKILL.md).

## Ручная проверка (browser-smoke)

`npm run dev` → пройти новую тему/урок (теория → сессия → слова озвучиваются), а для
нового кросс-предложения — довести соответствующую тему до ≥80% и убедиться, что
предложение всплывает. Сценарии и логин — [`../browser-smoke/SKILL.md`](../browser-smoke/SKILL.md).

## Типичные ошибки

- Переименовал `pt`/`lesson.id` существующего → осиротил прогресс.
- Вставил кросс-предложение в середину → сдвинул `sentenceKey` у последующих.
- `required` не совпал с реальным `word.pt` → предложение-призрак (никогда не видно).
- Потерял/исказил диакритику или взял бразильский вариант.
