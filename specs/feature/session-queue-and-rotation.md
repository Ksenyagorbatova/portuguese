# Очередь сессии (статичная, interleaved)

Статус: baseline (отгружено) · 2026-06-10 · клиентская (недетерминированная) половина

## Цель

Собрать **фиксированную** очередь карточек для тренировки: ученик с первой
карточки видит честный объём («1/20») и знает, когда сессия кончится. Слова
урока чередуются (interleaving — запоминается лучше тесного цикла по одному
слову), прогресс освоения сквозной между сессиями (живёт на сервере), урок
закрывается за несколько коротких подходов.

## Изменения данных / API

Чисто клиентская логика — серверных изменений нет. `getSrsState` (см.
[`srs-scheduling.md`](srs-scheduling.md)) отдаёт классификацию (`tags`) и
карточки (`cards` → `mcCorrect`/`typeCorrect`), а клиент строит очередь
([`src/lib/queue.ts`](../../src/lib/queue.ts)); сессия
([`src/components/Session.tsx`](../../src/components/Session.tsx)) только
двигает курсор. Недетерминированное держим ВНЕ Convex-queries.

## Поведение

**Очередь СТАТИЧНА:** собирается один раз при старте и после старта **не
растёт** — ошибка не вставляет переспрос, знаменатель «1/20» не меняется.
Недобранное слово вернётся в следующую сессию (прогресс на сервере).

**`buildLessonQueue`** — interleaved-проходы по **недоученным** словам урока
(`remainingReps > 0`; выученные не участвуют, пока урок не добит):
- проход = новый shuffle кандидатов, по ОДНОЙ карточке на слово; `due`-слова —
  первыми в ПЕРВОМ проходе;
- слово выбывает из проходов, когда набранные в очередь показы покрывают его
  остаток до «выучено» (`remainingReps = (MC_TARGET-mc)+(TYPE_TARGET-type)`);
- сосед-гард на стыке проходов: то же слово не идёт два раза подряд (swap с
  соседом; выполним, пока в проходе ≥2 слов);
- общий размер ≤ `SESSION_SIZE`; кросс-предложения (≤2, позиции 4/7) входят в
  бюджет: слов набирается ≤ `SESSION_SIZE − предложения`;
- урок добит целиком → одно-проходное повторение: каждое слово по одному
  показу (≤ бюджета).

**`buildMistakesQueue`** — мини-сессия «Повторить эти N слов» с финала: только
промахнутые слова, та же interleaved-механика, без предложений; каждое слово
получает **минимум один** показ (промах на уже выученном review-слове имеет
`remainingReps = 0`, но мини-сессию запускали ради него).

**`buildReviewQueue`** — слова из уроков, чья теория просмотрена: `due` (≤15),
`ongoing` (≤8), `learned` (≤3), все перемешаны; фолбэк — 10 случайных;
вставляется ≤3 предложения. Тоже статична (переспросов нет).

**Кросс-предложения** (`eligibleSentences`) появляются, только когда (а) все
`required`-слова выучены И (б) каждое `required`-слово приходит хотя бы из одной
темы, выученной на **≥80%** (`SENTENCE_TOPIC_THRESHOLD = 0.8`). Так сочетания
всплывают, когда тема почти освоена, — не раньше. Для слова с единственной темой
это прежнее правило «тема ≥80%»; для дублей `pt` в нескольких темах (farmácia,
olho, cabelo…) достаточно ЛЮБОЙ готовой темы — `wordTopicMap` отдаёт
`Map<pt, Set<topicKey>>`, иначе добавление дубля молча переносило бы гейт на
последнюю по порядку тему.

**Сессия** (`Session.tsx`): курсор по неизменной очереди; тип упражнения для
повторного показа слова выбирает `pickExerciseType` по внутрисессионному
прогрессу `WordProgress { mc, type }` (сидируется серверными счётчиками).
Промахи (quality 0) копятся уникально по слову → финал «Споткнулся на».
Строка прогресса показывает **позицию** (`idx+1/queue.length`), знаменатель
статичен.

## Ключевые решения и алгоритмы

Константы ([`src/lib/learning.ts`](../../src/lib/learning.ts)):
```
SESSION_SIZE = 20   // макс. карточек за сессию (слова + предложения)
```

**Почему вперемешку, а не «порция из N слов»:** тесный цикл из нескольких слов
по 6 повторов — скука и зубрёжка; чередование разных слов запоминается лучше и
держит внимание (interleaving; обсуждено и утверждено с владельцем продукта в
дизайн-ревью v2).

**Почему очередь не растёт:** растущий на глазах знаменатель («4/9 → 4/10»)
лишал ученика ощущения конца сессии; при упорных ошибках динамический переспрос
раздувал сессию до ~60 карточек. Камбэк слова теперь обеспечивают (а) несколько
показов в самой очереди (interleaved-проходы) и (б) следующая сессия — прогресс
mc/type серверный.

## Известные ограничения

- Очередь строится на клиенте — на разных устройствах порядок разный (by design).
- `SESSION_SIZE` ограничивает добор: слово может не «выучиться» за одну сессию
  и вернётся в следующую (как `ongoing`) — это осознанная замена динамическому
  переспросу.
- Сосед-гард не срабатывает, когда в проходе один кандидат (одно недоученное
  слово с несколькими оставшимися показами идёт подряд — неизбежно).
- Пилюля «сессия ≈ 5 мин» в строке урока — статичная оценка (сессии
  каппированы), не расчёт по фактическому остатку.
