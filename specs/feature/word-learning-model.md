# Смешанная модель освоения слова (узнавание + воспроизведение)

Статус: baseline (отгружено) · 2026-06-11

## Цель

Каждое слово осваивается за **два навыка** — узнавание (MC, выбор) и
воспроизведение (Type, ручной ввод) — тренируемых **вперемешку** в случайном
порядке. Слово считается выученным, только когда набраны ОБА навыка.

## Изменения данных / API

Два счётчика в таблице `progress`: `mcCorrect` (верные выборы) и `typeCorrect`
(верные ручные вводы), оба `v.optional` (старые строки читаются как 0).
`recordAnswer` принимает `mode` и при верном ответе (`quality>=1`) растит
соответствующий счётчик: `"mc"` → `mcCorrect`, `"type"` → `typeCorrect`. Третий
режим `"audio"` (аудирование, П.1) счётчики НЕ трогает — это экстра-тренировка
слуха, выученность она не двигает (см. «Поведение»).

`ExerciseType` — пять типов: три зрительных (`mc_pt_ru`, `mc_ru_pt`, `type_pt`)
плюс аудио `mc_audio_ru` («прослушай португальское слово, выбери русский
перевод»). `AnswerResult.mode` — `"mc" | "type" | "sentence" | "audio"`:
аудио-карточка ([`McExercise`](../../src/components/exercises/McExercise.tsx),
`mode: "audio_ru"`) шлёт серверный `mode: "audio"`.

## Поведение

Пороги ([`src/lib/learning.ts`](../../src/lib/learning.ts)):
```
MC_TARGET   = 3   // верных выборов (узнавание)
TYPE_TARGET = 3   // верных ручных вводов (воспроизведение)
```
**Выучено = `mcCorrect>=MC_TARGET && typeCorrect>=TYPE_TARGET`.** Модель —
**не только зрительная**: помимо трёх видимых упражнений (`mc_pt_ru`, `mc_ru_pt`,
`type_pt`) есть аудирование `mc_audio_ru`. Аудио появляется в ДВУХ местах:

- **Повторение (3-я ступень):** для уже ВЫУЧЕННЫХ слов `mc_audio_ru` —
  равноправный слот пула повторения (см. ниже).
- **Изучение (экстра):** пока слово ещё осваивается, но уже узнано хотя бы раз
  (`mc>=1`), с вероятностью `AUDIO_EXTRA_CHANCE` (`=0.18`, константа в
  [`learning.ts`](../../src/lib/learning.ts)) вместо обычного показа даём
  аудио-карточку СВЕРХ программы — тренировка слуха.

**Аудио НЕ двигает выученность.** Ответ на аудио-карточку шлёт серверный
`mode: "audio"` (не `"mc"`): он не растит ни `mcCorrect`, ни `typeCorrect` (и не
штрафует `lapses`). Поэтому, как и relief-выбор (см. ниже `TYPE_TAIL_MC_CHANCE`),
каждый аудио-показ удлиняет добор слова на одну карточку — очередь статична.

## Ключевые решения и алгоритмы

**Пороги ДУБЛИРУЮТСЯ на сервере** (`isLearned` в [`convex/progress.ts`](../../convex/progress.ts))
и на клиенте (`isWordLearned` в [`learning.ts`](../../src/lib/learning.ts)) —
**держать синхронно**: Convex бандлится отдельно и не делит модули с `src/`.

**`pickExerciseType(card, tag, rnd, audioOk)`** — тип следующего показа слова.
4-й параметр `audioOk` (булев) — доступно ли аудирование: его резолвит вызывающий
([`Session`](../../src/components/Session.tsx)) как
`canSpeakPortuguese() && !isMuted()` (звук не в mute И загружен португальский
голос). Функция остаётся чистой — гейт приходит снаружи.
- Пока слово не выучено (нужен MC или Type):
  - **Аудио-экстра** (П.1): `audioOk && mc>=1 && rnd()<AUDIO_EXTRA_CHANCE` →
    `mc_audio_ru` СВЕРХ программы (слово уже узнано хотя бы раз ⇒ был верный
    «выбор»). Не двигает выученность (`mode "audio"`). **`audioOk` стоит СЛЕВА**
    в условии → короткое замыкание: без аудио `rnd` не тратится, существующий
    микс/relief остаётся **побитово прежним**.
  - **Первое знакомство** (`mc===0 && type===0`) → **всегда MC** (`mc_pt_ru`/`mc_ru_pt`
    50/50): ручной ввод по никогда не виденному слову набрать нельзя. Инвариант
    без изменений (аудио-гейт выше требует `mc>=1`, поэтому на первом показе не
    стреляет).
  - Оба навыка в недоборе → честный 50/50 ввод/выбор.
  - **«Хвост из вводов»** (MC набран, Type нет) → ввод, но с шансом
    `TYPE_TAIL_MC_CHANCE` (=0.25) — выбор **сверх порога**: чистая череда
    ручных вводов утомляет (фидбэк владельца). Relief-показ `typeCorrect` не
    двигает — слово доберёт вводы в следующей сессии (очередь статична), это
    осознанная цена разнообразия; внутри одной очереди набор порогов поэтому
    НЕ гарантирован. Обратный хвост (Type набран, MC нет) не разбавляется —
    выборы лёгкие, проблема была в печати.
- Выучено (повторение): пул `["mc_pt_ru", "mc_ru_pt", "type_pt"]`; на `due` —
  лёгкий уклон в ручной ввод (`type_pt` добавляется в пул вторым ⇒ двойной вес);
  при `audioOk` в пул добавляется `mc_audio_ru` равноправным слотом — так
  выученное слово иногда приходит ушами. `rnd` инжектируется ради детерминизма
  в тестах.

**Классификация монотонна.** Счётчики только растут → слово не «разучивается».
Старые «выученные» строки уже имеют `mc>=3` (в прежней фазовой модели `type` рос
только после фазы выбора), поэтому правило «оба навыка» их не разучивает —
**миграция не нужна**.

## Известные ограничения

- Большой урок (до 10 слов) на первой тренировке длинный: каждое слово доводится
  до «выучено» за сессию (~`MC_TARGET`+`TYPE_TARGET` верных ответов на слово).
- Пороги дублированы (сервер/клиент) — рассинхрон порогов был бы тихим багом.
- Аудио-карточка (в учёбе и повторении) не двигает выученность (`mode "audio"`):
  каждый её показ — это +1 карточка к добору слова в статичной очереди (осознанная
  цена тренировки слуха). При выключенном звуке / без TTS аудио не выпадает
  (гейт `audioOk`), и микс остаётся прежним зрительным.
