# Рекомендации v4 — следующий горизонт (6 фич)

Ветка: `feat/recommendations-v4` · PR: _(TBD)_ · Дата: 2026-06-11 · Статус: готово к ревью

## Цель

Реализовать все 6 рекомендаций пакета «дизайн-ревью 2026 v4 — что дальше» поверх
принятого v2. Это не исправления долга, а новая ценность: тренировка восприятия
на слух, возвращаемость без давления, эмпатия к «вредным» словам, эмоциональный
финал курса, уважение к контексту использования (mute, хаптика). Источник —
`design_handoff_v4/README.md` (UI-спеки, гейты, acceptance).

Порядок (зависимости): **3 → 1 → 6** (mute — фундамент для аудирования и
хаптики), затем независимые **2, 4, 5**.

## Изменения данных / API

**Convex-схема ([`convex/schema.ts`](../../convex/schema.ts)):**
- `progress.lapses: v.optional(v.number())` — накопительные провалы (quality 0).
- `userStats.bestStreak: v.optional(v.number())` — максимум стрика за всё время.
- `userStats.startedAt: v.optional(v.string())` — день первого ответа (YYYY-MM-DD).

Все три — `optional`: старые строки их не несут, читаются как 0/null, бэкфилятся
при следующем ответе. Миграция не требуется (поля независимы от SM-2 и
классификации). `dataModel.d.ts` выводит `Doc` прямо из `schema.ts`, регенерация
`_generated` не нужна.

**`convex/progress.ts`:**
- `recordAnswer.mode` += `"audio"` (аудио-экстра, П.1): НЕ растит mc/type и НЕ
  штрафует lapses; seen/correct/streak и SM-2 — как обычно.
- `recordAnswer` копит `lapses += quality === 0 && mode !== "audio" ? 1 : 0`
  (независимо от SM-2 — расписание/классификацию не трогает); возвращает в `card`.
- `recordAnswer` стрик-блок переписан: считает `streak`/`lastDay`, затем единым
  `patch` бэкфилит `bestStreak = max(prev, streak)` и `startedAt ??= today`
  (одно безвредное лишнее write на том же дне ради бэкфила легаси-строк).
- `getSrsState` отдаёт `lapses` в карточках, `bestStreak`/`startedAt` на верхнем
  уровне (fallback `bestStreak ?? streak ?? 0`, `startedAt ?? null`).

**Клиентские типы ([`src/lib/types.ts`](../../src/lib/types.ts)):**
- `ExerciseType` += `"mc_audio_ru"`; `AnswerResult.mode` += `"audio"`.
- `CardFields.lapses?: number` (опционально — фикстуры тестов его не задают, пин-
  матрица планировщика его не сверяет; на сервере поле обязательное).
- `SrsState` += `bestStreak: number`, `startedAt: string | null`.
- `adaptSrs` ([`src/lib/srs.ts`](../../src/lib/srs.ts)) прокидывает новые поля,
  `lapses ?? 0`.

## Поведение (для пользователя)

- **Mute (П.3).** 4-я icon-кнопка в шапке между стриком и темой:
  `volume`/`volume-off`, aria «Звук: включён/выключен». Глушит авто-озвучку после
  ответа; ручной 🔊 звучит всегда. Переживает перезагрузку (localStorage
  `pt-muted`).
- **Аудирование (П.1).** Аудио-карточка: зона прослушивания вместо текста,
  авто-плей один раз, тап — повтор, второй тап — медленно. pt-текста нет на экране
  до ответа; варианты — русские; хоткеи 1–5/A–E работают; фидбэк показывает слово
  письменно. При mute или без TTS аудио-карточки не выпадают. Появляется в двух
  местах:
  - **в повторении** — выученное слово (mc≥3 и type≥3) иногда приходит ушами
    (равноправный слот пула, на due — реже);
  - **в изучении** (после теории) — как ЭКСТРА: после хотя бы одного верного
    выбора (mc≥1), пока слово ещё осваивается, изредка (`AUDIO_EXTRA_CHANCE`)
    вместо обычного показа даём аудио. Эта аудио-карточка **не двигает
    выученность** (серверный mode `"audio"` не растит mc/type и не штрафует
    lapses) — чистая тренировка слуха. Частота умеренная (~1 на слово), как
    relief: каждый такой показ удлиняет добор на одну карточку.
- **Хаптика (П.6).** Короткая вибрация на верный/неверный/retry (мобайл);
  уважает mute; десктоп — тихо.
- **Прогноз (П.2).** При due=0 под баннером «Все повторения сделаны» — строка
  «Завтра/В пятницу к повтору: N слов». Нечего планировать — строки нет.
- **Липучки (П.4).** В разборе ошибок у слова с lapses≥5 — бейдж «даётся тяжело»
  + ссылка «Перечитать теорию «{урок}»» на теорию первой липучки. Нигде больше.
- **Финал курса (П.5).** При 100% всех тем после сессии урока — экран
  «Курс пройден!» (флаг, эмодзи, 3 стат-плитки, CTA «Повторение продолжается»)
  ВМЕСТО Complete, один раз (localStorage `pt-course-complete-seen`).

## Ключевые решения и алгоритмы

- **Гейт аудио вне чистой функции.** `pickExerciseType(card, tag, rnd, audioOk)` —
  `audioOk` булев параметр, резолвит вызывающий (`Session`:
  `isSpeechSupported() && !isMuted()`, считается на каждом `advance` — mute мог
  переключиться внутри сессии). Для ВЫУЧЕННЫХ слов аудио — равноправный слот пула
  (на due уклон в ввод, type_pt с двойным весом). Инвариант «первый показ → MC»
  без изменений.
- **Аудио-экстра в изучении = режим `"audio"`, не двигает выученность.** В
  `pickExerciseType` (ветка недоученного) при `audioOk && mc>=1 &&
  rnd()<AUDIO_EXTRA_CHANCE` возвращаем `mc_audio_ru` СВЕРХ программы. Чтобы такой
  ответ не растил mastery, введён серверный mode `"audio"` (`recordAnswer`,
  `AnswerResult`, `predictCardAfterAnswer`): он НЕ инкрементит mc/type и lapses,
  но считает seen/correct/streak. SM-2 от режима не зависит → выученное due-слово,
  отвеченное ушами, нормально двигает расписание (`dueReview`), а недоученное
  получает фикс-шаг «завтра» (mc/type стоят → не graduating). `audioOk` слева в
  условии ⇒ короткое замыкание: без аудио `rnd` не тратится, существующий
  микс/relief остаётся побитово прежним (важно для детерминизма тестов).
- **Авто-озвучка → speakAuto.** Разделение «авто/ручное» в `speech.ts`:
  `speakAuto` (no-op при mute) в `finish()`/`check()` упражнений; для `audio_ru`
  авто-озвучку в `finish` НЕ повторяем (слово только что звучало). Авто-плей
  аудио-карточки — `speakAuto` в mount-эффекте (паттерн `useEffectEvent`, компонент
  keyed по idx → «один раз» = mount).
- **lapses вне SM-2.** Счётчик копится независимо; на `interval`/`ef`/`due`/
  классификацию не влияет (анти-инфляционный инвариант не затронут). Порог
  `LEECH_THRESHOLD=5` — чисто клиентский (сервер только копит).
- **Прогноз — локальные календарные дни.** `nextReviewForecast(cards, now)`:
  группирует будущие `due` по локальным дням (`setHours(0,0,0,0)`), берёт ближайший
  СТРОГО после сегодня (сегодняшние = due, не показываем), форматирует «Завтра» /
  «Во вторник» (винительный, у вторника «во»).
- **Финал — once-гейт в Session.** `Shell.courseCompleteOf(origin)` отдаёт
  цифры (всего слов/тем, `daysSinceStart`, `bestStreak`) при 100% всех тем и
  origin-урок; `Session` показывает `CourseComplete` при `courseComplete != null`
  и не-виденном флаге, пишет флаг в эффекте только когда экран реально показан
  (ранний выход не «сжигает» показ). `CourseComplete` — чистый презентационный,
  переживает `days=null` (плитка «дней» исчезает).
- **`tag` сохранён в сигнатуре** `pickExerciseType` (due-уклон) вместо удаления —
  чтобы не менять 2 вызова в Session и ~13 в тестах.

## Тестирование

- **Backend** (`convex/progress.test.ts`): `lapses` растёт только на quality 0 и
  отдаётся в `getSrsState`; `startedAt` фиксируется первым ответом и не меняется;
  `bestStreak` держит максимум при сбросе стрика. Существующая пин-матрица
  планировщика — зелёная (lapses её поля не сверяет).
- **Unit** (`src/lib`): `learning.test` — due-распределение, аудио в пуле только
  для выученных и при audioOk, никогда для недоученных; `speech.test` —
  setMuted/isMuted/персист, speakAuto no-op при mute, ручной speak в обход,
  isSpeechSupported; `haptics.test` — гейт mute и отсутствие vibrate; `srs.test` —
  adaptSrs прокидывает новые поля, nextReviewForecast («Завтра»/день недели/
  «сегодня»-пропуск/null), daysSinceStart.
- **CT**: `McExercise.ct` — audio_ru (зона, pt не в DOM до ответа, ru-варианты,
  хоткеи); `Header.ct` — mute-тоггл (иконка/лейбл/onToggleMute/позиция);
  `ReviewTab.ct` — строка прогноза есть/нет; `Complete.ct` — бейдж липучки +
  ссылка на теорию, и их отсутствие; `CourseComplete.ct` — итог/CTA/days=null/
  плюрализация; `Session.ct` — once-гейт финала (показ один раз, потом Complete).

`npm run verify` (typecheck + lint + 117 unit + 73 backend + 133 CT) и
`npm run build` — зелёные.

## Известные ограничения / дальнейшие шаги

- Проверка ответа аудио-карточки — на клиенте (как и везде): сервер доверяет
  `mode: "mc"` и `quality`. Аудио — это MC по навыку узнавания.
- Финал курса показывается один раз на устройство (localStorage); смена
  устройства/очистка storage покажет его снова. Приемлемо для разовой эмоции.
- Затронуты подсистемы word-learning-model (аудио, lapses), training-ui-and-shell
  (mute, финал), session-queue-and-rotation (выбор типа audioOk) — при следующей
  ревизии baseline-спек отразить там же.
- НЕ входит (отклонено владельцем): PWA, пилюля времени, статистика/графики,
  бейджи-достижения, соц-фичи, изменения SM-2.
