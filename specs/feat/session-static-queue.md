# Статичная сессия, разбор ошибок, финал-трамплин (дизайн-ревью v2, блок A)

Ветка: `feat/session-static-queue` · 2026-06-10 · готово (PR 1/3 серии
дизайн-ревью v2; далее блок B #4–6 и блок C #7–10)

## Цель

Реализовать блок «механика сессии» (#1–3) из дизайн-ревью v2
(handoff-пакет `design_handoff_review_v2`):

1. Сессия — фиксированные ≤20 карточек из всех недоученных слов урока
   вперемешку; знаменатель счётчика статичен; прогресс сквозной между сессиями.
   Раньше урок дрилился целиком с динамическим переспросом: ~60 карточек без
   видимого конца, счётчик «4/9 → 4/10» рос на глазах.
2. Финал показывает разбор ошибок («Споткнулся на») и кнопку «Повторить эти N
   слов» — момент максимальной восприимчивости не теряется.
3. Финал — «трамплин»: убран укор «Ещё N слов ждут повторения», CTA ведёт
   вперёд по фактическому прогрессу (продолжить урок → следующий урок →
   следующая тема), включая перекат через границу темы (раньше после
   последнего урока темы CTA исчезал — тупик).

## Изменения данных / API

Серверных изменений нет — чисто клиент. Прогресс mc/type уже хранится на
сервере per-word (`convex/progress.ts`), поэтому «сквозной» добор между
сессиями работает сам по себе.

Новые клиентские типы ([`src/lib/types.ts`](../../src/lib/types.ts)):
`NextStep` (`continue { remaining } | lesson | topic`), `CompleteHeading`
(`"topic" | "lesson" | "session"`).

## Поведение

- Новый урок на 10 слов → первая сессия ровно 20 карточек («1/20 … 20/20»),
  знаменатель не меняется ни при каких ответах; до первого повтора любого
  слова успевают показаться все недоученные слова (interleaving).
- Ошибка не вставляет переспрос; недобранное слово возвращается в следующей
  сессии («Продолжить урок (ещё N слов)»).
- В строке урока с недоученными словами — пилюля «сессия ≈ 5 мин»
  (соседствует с «📖 новая»; у добитых уроков нет).
- Финал: при промахах (quality 0) — блок «Споткнулся на» (до 5 строк
  «pt — ru», кнопка 🔊 `speak(pt)`) и «Повторить эти N слов» → мини-сессия
  только из этих слов той же статичной механикой (без предложений; промах на
  уже выученном review-слове получает минимум один показ). Предложения в
  разбор не попадают.
- Финал-трамплин: «Ещё N слов ждут повторения» удалена; «К повторению (N)»
  с числом `min(dueCountAll, REVIEW_DUE_LIMIT)`; primary-CTA:
  «Продолжить урок (ещё N слов)» / «Следующий урок: …» / «Следующая тема: …»
  (при теме ≥ `SENTENCE_TOPIC_THRESHOLD` и наличии следующей темы; ведёт через
  `openLesson` — с теорией, если не просмотрена). Для review-сессий — «Ещё
  раз» как раньше. «Ещё раз» остаётся ghost при шаге вперёд и скрывается при
  «Продолжить урок» (дублировал бы primary).
- Заголовок финала: «Тема закрыта!» (100% слов темы) / «Урок выучен!» /
  «Сессия завершена!».

## Ключевые решения и алгоритмы

- **Interleaved-проходы** (`interleavedReps`, [`src/lib/queue.ts`](../../src/lib/queue.ts)):
  проход = shuffle недоученных слов, по одной карточке на слово; слово
  выбывает, когда набранные показы покрывают `remainingReps =
  (MC_TARGET−mc)+(TYPE_TARGET−type)`; due-слова первыми в первом проходе;
  сосед-гард на стыке проходов (swap, выполним при ≥2 кандидатах). Вперемешку,
  а не «порция из 5 слов» — утверждено в дизайн-ревью (interleaving
  запоминается лучше тесного цикла).
- **Бюджет**: слова ≤ `SESSION_SIZE − число предложений`; предложения (≤2)
  врезаются на позиции 4/7 как раньше — общий размер ≤ `SESSION_SIZE = 20`.
- Урок добит → одно-проходное повторение (каждое слово по разу);
  `buildReviewQueue` не менялась (лимиты 15/8/3), статичность ей дал отказ от
  переспроса в `Session`.
- **`Session.tsx`**: рабочая очередь = проп `queue` (иммутабельна), удалены
  `items`/`setItems` и вставка переспроса; `WordProgress` без `shown` (CAP
  удалён); `wp` по-прежнему двигает `pickExerciseType` для повторных показов
  слова внутри очереди. Промахи копятся уникально по `wKey`.
- **`nextStepOf`/`headingOf` в `Shell`** считаются по реактивным
  `lessonStats`/`topicStats` (Convex) — к моменту финала ответы сессии уже
  учтены; короткая гонка последней мутации самоисправляется реактивным
  обновлением. Мини-сессия наследует `origin` исходной.
- Из `learning.ts` удалены `shouldRequeue`, `requeuePosition`,
  `SESSION_REQUEUE_CAP`, `REQUEUE_GAP`; добавлены `SESSION_SIZE` и
  `remainingReps`.

## Известные ограничения / дальнейшие шаги

- Сосед-гард бессилен, когда осталось одно недоученное слово (один кандидат в
  проходе) — допустимые соседние дубли.
- «сессия ≈ 5 мин» — статичная оценка, не расчёт.
- Гонка последней мутации: долю секунды финал может показывать «Продолжить
  урок (ещё 1 слово)», пока сервер не подтвердил добитие, — реактивно
  самоисправляется.
- Блоки B (#4–6: спойлер-заметка, focus-visible, контраст) и C (#7–10: галочка
  стрика, ConfirmDialog, чипы на таче, медленная озвучка) — отдельными PR.
