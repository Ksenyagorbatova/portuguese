# Клавиатурная доступность и a11y

Ветка: `fix/a11y-keyboard` · PR: — · Дата: 2026-06-10 · Статус: готово

## Цель

Закрыть подтверждённые находки ревью по доступности: ключевые экраны были
неоперабельны с клавиатуры (кликабельные `div` без фокуса), нарисованные кейкапы
A–E в выборе не работали, динамический фидбэк не озвучивался скринридером,
португальский текст внутри русского документа не был размечен `lang`.

## Поведение (для пользователя)

- **Вкладка «Темы»**: шапка темы и строка урока фокусируются Tab'ом и
  открываются Enter/Space; у шапки-аккордеона корректный `aria-expanded`.
  Enter на вложенной кнопке «Теория» открывает только теорию, не урок.
- **Выбор (MC)**: клавиши `1–5` и латинские `A–E` (любой регистр, без
  Cmd/Ctrl/Alt, без автоповтора) выбирают соответствующую опцию — кейкапы теперь
  функциональны. Хоткеи молчат после ответа и для уже промазанной (disabled)
  опции. После ответа фокус автоматически на «Дальше» → Enter ведёт дальше
  (работает во всех упражнениях — autofocus в общем `NextButton`).
- **Конструктор предложений**: плитки банка и собранного ответа — настоящие
  кнопки; упражнение полностью собирается и проверяется с клавиатуры
  (Tab + Enter). Использованные плитки выпадают из tab-порядка (`disabled`).
- **Теория**: flip-карточка — кнопка (Enter/Space переворачивают и озвучивают),
  состояние — `aria-pressed`.
- **Скринридер**: вердикты «Верно!»/«Правильно:…»/«Не совсем!» озвучиваются
  (`role="status"` + `aria-live="polite"`); полоса прогресса сессии —
  `role="progressbar"` c `aria-valuenow/min/max` и лейблом «Позиция в сессии»;
  поля входа несут `aria-label` (Email/Пароль), а не только placeholder.
- **Произношение**: точечный `lang="pt-PT"` на португальском тексте — вопрос в
  MC pt→ru, опции в MC ru→pt, pt-слово в фидбэке (MC/Type/Sentence), плитки
  конструктора, pt-сторона flip-карточки. Русские строки не размечены.

## Ключевые решения

- **`<button>` против `role="button"`.** Настоящие кнопки везде, где нет
  вложенных интерактивов: шапка темы, плитки конструктора, flip-карточка.
  Строка урока осталась `div role="button" tabIndex={0}` + Enter/Space —
  внутри неё живёт кнопка «Теория», а button-в-button невалиден; в keydown
  guard `e.target !== e.currentTarget`, чтобы Enter на «Теории» не открывал урок.
- **UA-стили кнопок погашены с нулевой специфичностью** — блок
  `:where(button.m-topic-head, button.m-wtile, button.m-atile, button.m-flip)`
  в конце `src/index.css`: существующие классовые правила побеждают, вёрстка и
  имена классов (m-*) не изменены; только `width:100%` для шапки и flip-карточки
  (button не растягивается сам).
- **Хоткеи MC** — `useEffectEvent` (стабильный в React 19.2) + один
  `useEffect`-слушатель `keydown` на `window` с очисткой: handler читает свежие
  `resolved/wrongPicked/options` без переподписки. Игнорируем `e.repeat`,
  модификаторы, фокус в input/textarea/contentEditable. Только латиница и
  цифры — кириллица (раскладка RU) не стреляет. `finish()`/мутации не тронуты
  (их параллельно правит ветка network-resilience) — хоткей зовёт существующий
  `choose()`.
- **Кейкап `m-opt-key` скрыт от имени кнопки** (`aria-hidden`) — имя опции
  остаётся чистым текстом варианта.
- **Латентная коллизия ключей опций починена**: `key={o.pt}` →
  `key={wKey(o.lessonKey, o.pt)}` (в контенте есть дубли `pt` в разных уроках).
- **Enter → «Дальше»** реализован autofocus'ом в `NextButton` (Feedback.tsx) —
  без отдельного Enter-слушателя; одинаково работает в MC/Type/Sentence.
- `aria-valuenow = idx+1` (позиция, как в счётчике `1/N`), `min=0`,
  `max=items.length`.
- В SignIn — `aria-label`, а не видимые `<label>`: вёрстка формы не меняется;
  `minLength` не тронут (другая ветка).

## Тестирование

Playwright CT (новые/обновлённые, все в `*.ct.tsx` рядом с компонентами):

- `TopicsTab`: Enter/Space на строке урока открывают урок; Enter на вложенной
  «Теории» не открывает урок; шапка темы — кнопка, toggle с клавиатуры +
  `aria-expanded`. Существующий селектор «Теория» уточнён `exact: true`
  (строка-`role=button` теперь содержит «Теория» в имени).
- `McExercise`: хоткей-цифра и хоткей-буква выбирают опцию; хоткеи инертны для
  disabled-опции и после ответа; Enter после ответа жмёт автофокусную «Дальше»;
  `lang="pt-PT"` на вопросе (pt→ru) и опциях (ru→pt).
- `SentenceBuilder`: сборка и проверка только клавиатурой; плитки — кнопки с
  `lang="pt-PT"`.
- `Theory`: flip-карточка — кнопка, Enter/Space переворачивают, `aria-pressed`,
  `lang` на pt-стороне.
- `Session`: `role="progressbar"` + `aria-label`/`aria-valuenow/min/max`.
- `Feedback`: `ResultFeedback`/`RetryBox` — live-регионы (`aria-live="polite"`,
  `role="status"`); `NextButton` автофокусен и активируется Enter'ом.
- `SignIn`: поля находимы по `getByLabel("Email")`/`getByLabel("Пароль")`.

`npm run verify` (typecheck + lint + Vitest 95 + CT 63) и `npm run build` —
зелёные.

## Известные ограничения / дальнейшие шаги

- Кастомных стилей `:focus-visible` нет — используются дефолтные кольца
  браузера (видимы, но не брендированы).
- `TypeExercise` и `text.ts` не тронуты (зона ветки пунктуации); его фидбэк
  получил `lang`/aria-live автоматически через общий `Feedback.tsx`.
- Семантику `wrongPicked`/`isCorrectOpt` по `o.pt` (та же латентная коллизия,
  что и у `key`) не расширяли — вне объёма задачи и зоны другой ветки.
