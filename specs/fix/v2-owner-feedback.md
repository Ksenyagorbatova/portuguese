# Правки по фидбэку владельца после дизайн-ревью v2

Ветка: `fix/v2-owner-feedback` · 2026-06-11 · готово

## Цель

Пять правок по живому фидбэку владельца после деплоя серии v2 (#36–#38):

1. **Озвучка из фидбэка.** После ответа слово хочется переслушать — кнопки не
   было (только авто-проигрыш и 🔊 в вопросе pt→ru).
2. **Пилюля «сессия ≈ 5 мин» — убрать.** Лишний шум в строке урока (введена
   в #36 по хендоффу, владелец отменил).
3. **Гашение служебных хинтов** — отложенный опциональный пункт #4 хендоффа,
   владелец попросил сделать.
4. **Два флага 🇵🇹 подряд** в совете теории: разметка (`m-tip-flag`) рисует
   свой флаг, а тексты `tip` в контенте начинались со второго.
5. **Метка «следующий повтор» дёргалась**: фидбэк показывался сразу с «—»,
   а реальный текст («завтра») прилетал после сетевого roundtrip'а.

## Поведение

1. В `WordFeedback` рядом с «pt — ru» — круглая кнопка 🔊 (`m-fb-audio`,
   24px, в focus-кольцах): `speakSmart` — повторный тап в течение 4с играет
   медленно; `aria-label` «Прослушать (второй тап — медленно)».
2. Пилюли «сессия ≈ 5 мин» больше нет нигде (рендер, CSS `.m-pill-est`,
   тесты, упоминания в baseline-спеках).
3. Хинты «Акценты и пунктуация необязательны…» (ввод) и «Нажми на
   карточку…» (теория) показываются по `HINT_SHOW_LIMIT` (=3) раза и гаснут
   насовсем. Счётчики в localStorage (`pt-hint-accents-seen`,
   `pt-hint-flip-seen`); показ = маунт компонента, решение фиксируется на
   маунте (хинт не исчезает посреди карточки), учёт — ровно раз за маунт
   (ref-guard, честно и под StrictMode). Недоступное хранилище (приватный
   режим) → хинт остаётся постоянным, без падений.
4. Из всех 23 `tip` в [`convex/content.ts`](../../convex/content.ts) убран
   префикс «🇵🇹 » (только текст; `lessonKey`/`pt` не тронуты — прогресс цел);
   флаг рисует разметка. Guard-тест в `content.test.ts` не даст вернуться.
   Прод-контент обновится сидом на деплое (идемпотентный upsert театрии).
5. **Мгновенная метка повтора**: упражнение считает «следующий повтор»
   локальным зеркалом планировщика
   ([`src/lib/srsPredict.ts`](../../src/lib/srsPredict.ts),
   `predictCardAfterAnswer`) и показывает финальный текст ВМЕСТЕ с вердиктом.
   Ответ сервера тихо поправляет метку при расхождении (устаревший
   `card`-проп — например, офлайн-очередь); отказ мутации — как раньше:
   «—» + «Не удалось сохранить ответ» (предсказание в этом случае ложно —
   расписание не записано).

## Ключевые решения

- **Зеркало планировщика узаконено пином** (как дубль порогов
  MC/TYPE_TARGET): матрица в
  [`convex/progress.test.ts`](../../convex/progress.test.ts) гонит всю жизнь
  слова (знакомство → добор → выпуск → due-повторы q2/q1/q0 → ранняя
  практика/лапс → кламп MAX_INTERVAL) через настоящий `recordAnswer` и
  сверяет каждое поле с предсказанием (`due` — с допуском 5с на разницу
  `Date.now`). Разъедутся формулы — упадёт пин. Инвариант добавлен в скилл
  [`srs-invariants`](../../.claude/skills/srs-invariants/SKILL.md) (п. 6b).
- Альтернатива «подождать мутацию ~300мс перед фидбэком» отклонена: задержка
  вердикта на каждый ответ + дёрганье остаётся на медленной сети.
- Хинты: «показ» = маунт (3 первые карточки ввода / 3 открытия теории), без
  per-сессионной логики — простота важнее точной семантики «сессий».

## Известные ограничения

- Точность мгновенной метки зависит от свежести `card`-пропа (реактивный
  `getSrsState`); при отставании (быстрые ответы на медленной сети) сервер
  тихо поправит текст — это та же «правка после roundtrip'а», но только в
  редком расхождении, а не на каждом ответе.
- Гашение хинтов — per-устройство (localStorage), сбрасывается очисткой
  данных сайта.
