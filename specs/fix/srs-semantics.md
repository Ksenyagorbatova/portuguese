# Семантика SRS: честный стрик, lapse ранней практики, пин порогов

Ветка: `fix/srs-semantics` (стековая, от `fix/backend-validation`) · 2026-06-10 · статус: готово

## Цель

Три смысловых фикса планировщика/статистики: (1) стрик считался нечестно — рос на
любом первом ответе дня и никогда не сбрасывался, а день брался по UTC сервера,
не по дню пользователя; (2) полный провал выученного слова при ранней практике
игнорировался — слово с далёким due продолжало «спать», хотя пользователь его уже
забыл; (3) пороги освоения дублированы сервер↔клиент и ничем не пинились —
рассинхрон констант не ловился тестами.

## Изменения данных / API

- `progress.recordAnswer` — новый аргумент `clientDay: v.optional(v.string())`
  (локальная дата клиента `YYYY-MM-DD`; валидация: формат-regex И парсимость
  `Date.parse` — «2026-13-99» проходит regex, но непарсим; отсутствует/невалиден →
  fallback на серверную UTC-дату — graceful для закэшированного старого фронта).
- Семантика стрика: тот же день → без изменений; `lastDay` ровно вчера →
  `streak+1`; пропуск ≥1 дня → сброс в `1`; `clientDay` РАНЬШЕ `lastDay`
  (смена пояса на запад) → no-op (не сбрасывать).
- Формат `userStats.lastDay`: новые значения — `YYYY-MM-DD`; легаси
  (`toDateString()`, «Mon Jun 09 2026») парсится через `Date.parse` для
  сравнения и перезаписывается новым форматом при первом сдвиге дня. Отдельная
  миграция данных не нужна.
- Lapse: ветка «выученное, ещё не due» больше не игнорирует ЛЮБОЙ ответ —
  при `quality === 0` теперь `interval = 1`, `due = now + DAY`; `ef` не трогаем.
  `quality` 1/2 — поведение прежнее (расписание не трогаем).
- Клиент: `McExercise`/`TypeExercise` передают `clientDay: localDay()` в
  `recordAnswer`; новый хелпер `localDay()` в `src/lib/day.ts`
  (`toLocaleDateString("en-CA")` → `YYYY-MM-DD` в локальной TZ).

## Поведение (для пользователя)

- Стрик отражает реальную непрерывную серию дней: пропустил день — серия
  начинается заново; занимался вчера и сегодня — серия растёт; день считается по
  часовому поясу пользователя.
- Забытое (quality=0) выученное слово при досрочной тренировке всплывёт уже
  завтра, а не через месяцы по старому расписанию.

## Ключевые решения и алгоритмы

- **Сравнение дней** — `diffDays = round((parse(today) − parse(lastDay)) / DAY)`:
  ISO-даты парсятся в UTC-полуночи (разница — точные целые), легаси
  `toDateString` — в локальной полуночи рантайма; `Math.round` гасит TZ-сдвиг
  (<12 ч). Непарсимое `lastDay` → `Infinity` → ветка сброса.
- **`clientDay` раньше `lastDay`** — отдаём текущий стрик и НЕ перезаписываем
  `lastDay` (остаётся поздний день): перелёт на запад не должен ни сбрасывать
  серию, ни давать `+1` за «вчера» второй раз.
- **Lapse не трогает `ef`** — рационал: ef-штраф остаётся на due-повторах,
  ранний lapse только приближает повтор. Анти-инфляционный инвариант
  («интервал двигается только на событие повторения», см.
  [`srs-scheduling.md`](../feature/srs-scheduling.md)) не нарушается: это
  сужение интервала до 1, без умножения на `ef`.
- **Кросс-слойный пин порогов** — backend-тесты импортируют
  `MC_TARGET`/`TYPE_TARGET` из `../src/lib/learning` (чистый модуль; работает и
  в edge-runtime Vitest, и в `tsconfig.test.json`); graduate-циклы и явные тесты
  «выпуск ровно на добирающем ответе» сделаны так, что рассинхрон ЛЮБОЙ из двух
  копий констант (клиентской или серверной) роняет тест в обе стороны
  (порог меньше → выпуск раньше добора, больше → не на доборе).
- Правки `McExercise`/`TypeExercise` строго минимальны (только аргумент в вызове
  `recordAnswer`) — эти файлы параллельно правит другая ветка.

## Известные ограничения

- Сервер доверяет присланному `clientDay` (как и `quality`/`mode`) — личный
  тренажёр, защита от самообмана не цель.
- Легаси-`lastDay` сравнивается с точностью до TZ-сдвига <12 ч (гасится
  округлением); экзотические пояса ±13/14 ч теоретически могут на сутки ошибиться
  один раз — значение мигрирует в `YYYY-MM-DD` при первом СДВИГЕ дня (ветки
  «тот же день» и «clientDay раньше lastDay» `lastDay` не переписывают).
- Однократный эффект смены базиса дня на деплой-границе: легаси-`lastDay` писался
  по UTC-дню сервера, новый день — локальный день клиента. Пользователь ВОСТОЧНЕЕ
  UTC, чей последний до-деплойный ответ пришёлся на первые часы после местной
  полуночи (по UTC это ещё «вчера»), при первом ответе после деплоя получит
  `diff=2` → ложный сброс; западнее UTC — симметрично пропущенный `+1`
  (`diff=0` вместо `1`). Однократно, самоизлечивается со следующим днём; кодом
  не чиним осознанно.
- Стрик по-прежнему без «заморозок»; SentenceBuilder не пишет SRS (как и раньше).
