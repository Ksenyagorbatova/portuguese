# Целостность контента: слова из теории + инварианты-тесты

Ветка: `fix/content-integrity` · PR: (TBD) · 2026-06-10 · Статус: готово к ревью

## Цель

Два подтверждённых бага ревью в [`convex/content.ts`](../../convex/content.ts):

1. **30 строк** из `theory.sections[].words` не существовали как слова своего урока.
   `Theory.tsx` рендерит секцию фильтром `lesson.words.filter((w) => sec.words.includes(w.pt))`
   — такие карточки **молча не показывались** («Расширенная семья» показывала 2 из 6,
   «Природа» — 1 из 6 и т.д.).
2. Кросс-предложение `cs_0008` («O restaurante é perto daqui.», `required:
   ["restaurante", "perto"]`) **никогда не всплывало** — слова `perto` не существовало
   ни в одном уроке, а гейт сверяет `required` с множеством выученных `pt`.

Решение владельца: добавить недостающие слова **полноценными словами** своих уроков
(п. 2 чинится добавлением `perto`), и закрепить весь класс багов валидационными
тестами контента.

## Поведение (для пользователя)

- Теория десяти уроков теперь показывает **все** слова своих секций.
- Новые слова участвуют в тренировке своих уроков как обычные слова
  (урок берёт все слова, каждое доводится до «выучено»).
- `cs_0008` становится достижимым: `perto` теперь существует (`city_2`) и может
  быть выучен.

## Ключевые решения и алгоритмы

- **Append-only.** Новые слова — строго в конец массива `words`: `order`
  захватывается сидом из порядка итерации, существующие пары `(lessonKey, pt)` и их
  `order` не сдвигаются.
- **`pt` побайтово равны строкам из `theory.sections`** — это и проверяет новый тест.
- **Дубли слов между уроками — норма модели данных** (grande и др. в `basics_1` и
  `basics_2`, farmácia в `city_1` и `body_2`, aqui/ali в `basics_2` и `city_2`):
  прогресс ключуется парой `(lessonKey, pt)`; прецеденты уже были (olho, cabelo).
  `ru` дублей идентичен существующим записям.
- **`note` только где реально полезен** (нюанс употребления): querer, logo,
  perto/longe. Остальные — без note, как их прототипы в соседних уроках.
- **Гейт кросс-предложений учитывает дубли тем (фикс по code-review).**
  `wordTopicMap` ([`src/lib/queue.ts`](../../src/lib/queue.ts)) строил `Map<pt,
  topicKey>` по принципу «последняя тема побеждает» — добавление `farmácia` в
  `body_2` молча переносило гейт cs_0007 («Onde é a farmácia?») с освоенной темы
  city на тему body. Теперь карта — `Map<pt, Set<topicKey>>`, и required-слово
  считается готовым, когда готова **хотя бы одна** из его тем (заодно чинит
  унаследованный кейс olho/cabelo для cs_0013). Для слов без дублей поведение
  не изменилось.
- **Новый [`convex/content.test.ts`](../../convex/content.test.ts)** — чистые
  инварианты поверх импорта `TOPICS`/`CROSS_SENTENCES`, без convex-test
  (подхватывается backend-проектом Vitest по маске `convex/**/*.test.ts`):
  1. **golden-снапшот всех пар `(lessonKey, pt)`** — отсортированный список в
     формате wKey (`lessonKey||pt`); исчезновение/переименование существующей пары
     роняет тест (защита прогресса). Обновление снапшота — осознанное действие:
     в диффе допустимы только добавленные строки.
  2. Каждый `required[]` кросс-предложения существует как `word.pt` хотя бы одного урока.
  3. Каждая строка `theory.sections[].words` существует среди `words[].pt` СВОЕГО урока.
  4. `answer === words.join(" ")` у всех кросс-предложений.
  5. Уникальность `(lessonKey, pt)` внутри урока; `lessonKey` / `topicKey` /
     `sentenceKey` — глобально.
  6. Ни в одном `pt`/`lessonKey` нет подстроки `"||"` (разделитель составного ключа wKey).

## Известные ограничения / дальнейшие шаги

- В части уроков (`numbers_2`, `verbs_2`, `body_2`, `home_1`) порядок карточек
  внутри секции теории слегка отличается от порядка перечисления в секции —
  новые слова стоят в конце массива `words` (append-only), существующие `order`
  не сдвигались. Чистая косметика; правится отдельной задачей перестановкой
  массива `words` (это безопасно — ключи не меняются), если владельцу важно.
- Первая тренировка пополневших уроков станет длиннее (урок берёт все слова) —
  известный компромисс проекта.
- У пользователей с освоенной темой добавленные слова временно снижают процент
  освоения темы (гейт кросс-предложений ≥80%) — естественное следствие любого
  добавления контента.
