# Устойчивость тренировки к сети: гонка двойного ответа, зависание на мутации, офлайн-индикатор, ErrorBoundary

Ветка: `fix/exercise-network-resilience` · PR: — · Дата: 2026-06-10 · Статус: готово к ревью

## Цель

Починить два подтверждённых ревью бага в упражнениях (McExercise/TypeExercise),
проявляющихся при медленной/оборванной сети, и добавить «мягкий офлайн» без
PWA/кэшей: индикатор разрыва соединения и корневой ErrorBoundary вместо белого
экрана.

1. **Гонка двойного ответа.** `finish()` вызывал `onAnswered` синхронно, а
   `setResolved` — только ПОСЛЕ `await recordAnswer(...)`. В окне сетевого
   roundtrip guard `if (resolved) return` не работал: двойной клик по опции или
   удержание Enter (авторепит keydown, guard на `e.repeat` отсутствовал) давали
   повторные `finish()` — двойной счёт сессии и раздувание
   `mcCorrect`/`typeCorrect` локально и на сервере (слово можно было «выучить»
   удержанием клавиши).
2. **Отказ/зависание мутации подвешивали упражнение.** Если `recordAnswer`
   реджектится, `setResolved` не выполнялся: фидбэк и «Дальше» не появлялись
   никогда + unhandled rejection, а счёт уже инкрементирован. Важнее: при
   **разрыве сети** промис мутации Convex вообще не реджектится (см. ниже) —
   упражнение висело бы до реконнекта.

## Факты о Convex-клиенте (проверено по докам context7 + исходникам convex 1.40.0)

- **Мутации при разрыве НЕ теряются и НЕ реджектятся**: клиент держит их в
  очереди в памяти и переотправляет при реконнекте
  (`RequestManager.restart()` в `browser/sync/request_manager.js` снова шлёт все
  inflight/неотправленные `Mutation`-сообщения; их промисы остаются pending до
  фактического выполнения). Реджект мутации — это ответ сервера (ошибка
  функции/авторизации), не сетевое событие. *Actions, в отличие от мутаций,
  при разрыве реджектятся — в проекте actions нет.*
- Состояние соединения — `useConvexConnectionState()` из `convex/react`
  (реактивный хук, есть в 1.40; поле `isWebSocketConnected`). Альтернативы
  `client.connectionState()` / `subscribeToConnectionState()` не нужны —
  хук уже подписан.

Следствие для дизайна: «UI ждёт ответа мутации» ломается в обоих сценариях
(reject → никогда; разрыв → неограниченно долго), поэтому UI от roundtrip
отвязан полностью.

## Поведение (для пользователя)

- Ответ в упражнении засчитывается ровно один раз: опции/инпут блокируются
  мгновенно, двойной клик и удержание Enter не дают второго ответа.
- Фидбэк и кнопка «Дальше» появляются СРАЗУ после ответа, не дожидаясь сервера:
  - сервер ответил → в фидбэке настоящая метка «следующий повтор: завтра/…»
    (подтягивается на лету, до этого «—»);
  - сети нет → метка остаётся «—», ответ доедет при реконнекте (очередь
    Convex), сверху висит баннер;
  - мутация отвергнута сервером → «—» + ненавязчивая пометка «Не удалось
    сохранить ответ.» (без обещания автоповтора — отвергнутая мутация не
    переотправляется).
- При разрыве соединения под хедером появляется баннер «Нет соединения —
  ответы сохранятся, когда сеть восстановится» (виден и в сессии), при
  реконнекте исчезает сам.
- Любая необработанная ошибка рендера/query показывает русский экран
  «Что-то пошло не так… Перезагрузите страницу — прогресс хранится на сервере»
  с кнопкой «Перезагрузить» вместо белого экрана.

## Ключевые решения и алгоритмы

- **Синхронный `pendingRef`** (Mc и Type): выставляется первой строкой
  `finish()` ДО любой асинхронщины; `choose()`/`check()` дополнительно
  проверяют `resolved || pendingRef.current`. Ref, а не state: обновление state
  не гарантирует закрытие окна «событие → применение обновления», ref закрывает
  его синхронно. Плюс `if (e.repeat) return` в `onKeyDown` (авторепит Enter).
- **UI не ждёт мутацию**: `setResolved({ ok, dueLabel: null })` синхронно в
  `finish()`, затем `recordAnswer(...).then(успех → метка, отказ → saveFailed)`.
  `onAnswered` (счёт сессии, ротация) и так был синхронным — порядок сохранён.
  Поздний `setResolved` после ухода с карточки безопасен (React 19 игнорирует
  setState размонтированного компонента). Ротация в сессии не зависит от ответа
  сервера: Session ведёт локальный stage-прогресс (`wp`).
- **Семантика пометок — честная**: «сохранится при восстановлении сети» обещает
  только БАННЕР (для очереди клиента это правда); пометка при reject говорит
  лишь «не удалось сохранить» (отвергнутую мутацию клиент не повторяет).
- **`SentenceBuilder` не трогали**: `recordAnswer` он не вызывает (проверено),
  его `setResolved` синхронный — гонки/зависания нет.
- **ErrorBoundary — классовый компонент** (`getDerivedStateFromError` +
  `componentDidCatch` с `console.error`): в React 19 это по-прежнему
  единственный механизм fallback-UI ошибок рендера (хук-аналога нет; дефолтный
  `onCaughtError` корня = console.error). Стоит внутри StrictMode, снаружи
  `ConvexAuthProvider` — ловит и ошибки провайдера/queries. Fallback на
  существующих классах `m-app`/`m-splash`/`m-btn` (тон Splash).
- **Никакого service worker / кэша данных / холодного офлайн-старта** — по
  договорённости. До первой загрузки офлайн по-прежнему Splash.

## Тестирование

Политика «сначала красный тест» соблюдена: все 5 новых сетевых CT-тестов
прогнаны на старом коде (красные: `answered = 2` в гонке; таймаут ожидания
фидбэка при reject), после фикса — зелёные; 8 существующих CT упражнений не
менялись и зелёные.

- **Стаб `useMutation`** (`src/test/mocks/convexReact.ts`) стал конфигурируемым
  через `window.__mutationMock`: `manual` (промис висит до `release()` —
  детерминированно держит окно roundtrip открытым), `reject`, счётчик `calls`.
  Дефолт без конфига — прежний мгновенный resolve (существующие CT не задеты).
  Грабли, на которые наступили и которые закреплены комментариями:
  - конфиг ставится ПОСЛЕ `mount` — первый mount в воркере навигирует страницу
    и стирает `window`;
  - задержки-таймеры вместо `manual` дают ложно-зелёный тест: на холодном CT
    воркере паузы CDP между действиями больше любой разумной задержки (окно
    закрывалось до второго клика);
  - страница CT переиспользуется между тестами → зачистка стабов в
    `beforeMount` (`playwright/index.tsx`) + `afterEach` (release зависших
    промисов).
- **CT Mc**: двойной клик в открытом окне roundtrip (второй — `dispatchEvent`
  мимо disabled-семантики, прицельно по sync-guard) → `onAnswered` и мутация по
  одному разу; reject → фидбэк, «—», пометка, «Дальше» работает; manual-окно →
  фидбэк с «—» сразу, после `release()` метка становится «завтра».
- **CT Type**: удержание Enter (`repeat: true` × 3 + повторный Enter) → один
  ответ, одна мутация; reject → фидбэк, «—», пометка, «Дальше».
- **CT OfflineBanner**: онлайн (дефолт стаба `useConvexConnectionState`) →
  баннера нет; офлайн через `hooksConfig` (применяется в `beforeMount`, т.е.
  гарантированно до первого рендера) → текст виден.
- **CT ErrorBoundary**: бросающий ребёнок (`src/test/mocks/Boom.tsx` — CT не
  позволяет определять компоненты в файле спеки) → fallback + кнопка
  «Перезагрузить»; без ошибки — дети как есть.
- `npm run verify` зелёный целиком: typecheck + oxlint + Vitest 95 (unit +
  backend) + Playwright CT 56. `npm run build` зелёный.

## Известные ограничения / дальнейшие шаги

- Очередь мутаций Convex живёт в памяти вкладки: закрытие/перезагрузка страницы
  в офлайне теряет неотправленные ответы (сознательный компромисс «мягкого
  офлайна» без PWA).
- На быстрой сети метка «следующий повтор» на мгновение показывает «—», затем
  значение — плата за мгновенный фидбэк; сама строка присутствует всегда
  (раскладка не прыгает, «Дальше» не смещается).
- Баннер появляется только после загрузки Shell (холодного офлайн-старта нет —
  как и раньше, Splash).
- Сетевой reject в `markTheorySeen` (Shell) не обрабатывается — она
  идемпотентна и некритична (теория просто снова откроется онбордингом);
  вне скоупа этой ветки.
- Браузерный смоук по `browser-smoke` перед PR — за отгружающим (worktree
  требует `npm run wt:setup` для локального Convex).
